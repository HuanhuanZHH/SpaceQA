# SpaceQA 评价规范与系统反思（2026-11-08）

## 1. 结论边界

当前系统可以把数据包整理成逐样本账本、执行确定性检查、生成八类缺陷候选/确认记录、计算概率污染指数、形成六维技术观测卡并提供文件、标注字段和图像区域回查。它不能在缺少独立参考真值时把模型候选包装成官方缺陷真值，也不能据此宣称路演集的官方 Precision、Recall 或 F1。

“数据材料缺失”和“系统功能未实现”分开记录：

| 情况 | 系统处理 | 能否宣称通过 |
| --- | --- | --- |
| 原始数据、字段字典、用途声明或独立参考未提供 | 保留在适用分母，状态为证据未决，并记录补充材料 | 不能把未决当通过 |
| 系统已执行规则、定位、程度和回查 | 输出证据、规则版本和哈希 | 可宣称已完成该项 |
| 系统没有相应检查或没有独立定位依据 | 输出未完成/候选状态和原因 | 不能宣称该项达标 |

## 2. 六维规则

六维是评价规范的结构，不是八类缺陷的同义词。

1. **完整性**：文件存在、标签可解析、字段齐备、形状/类型和缺失标识可测。
2. **标注质量**：类别契约、几何合法性、时间字段结构；真实类别、边界、漏标和虚标需要独立参考。
3. **样本对应关系**：数据—标签引用、一一对应、空间坐标和显式尺寸。
4. **覆盖与分布**：类别/事件/时间统计、重复和泄漏；若没有预期分布与允许偏差，只报告描述统计。
5. **文档与来源追溯**：说明文档、字段字典、版本、处理方法、文件哈希和运行链路。
6. **使用条件**：用途、权限、限制、可比性前提和接入约束。技术格式通过不等于许可和科学适用性通过。

每条检查使用四种状态：`通过`、`不通过`、`待判定`、`不适用`。适用但未实现的检查保留在分母；`不适用`只在数据类型契约明确不适用时使用。未决项给出分数区间，绝不自动填 0 或 100。

限定技术观测分为：

```text
dimension_observation = 100 × pass / (pass + fail)
```

分母只包括已完成且可核验的检查，适用未决数另列。完整科学质量分只有在六维材料齐全、适用检查全部完成、容差和排序规则与实现一致时才可计算。

## 3. 八类缺陷

| 编号 | 缺陷 | 可确定的证据 | 需要独立参考的部分 |
| --- | --- | --- | --- |
| L0-01 | 数据文件缺失 | 引用路径、文件存在性和哈希 | 无；L0-03作为同一可观测缺失条件保留别名 |
| L2-G | 边界与位置偏差 | 参考区域与预测区域的 IoU、中心距离或边界距离 | 目标区域真值 |
| L2-P | 类别标注错误 | 类别契约冲突 | 集合内类别的科学语义 |
| L2-T | 时段起止时刻抖动 | 可解析、顺序和端点差 | 独立事件端点和可信时间基准 |
| L2-F | 元数据尺寸矛盾 | 声明尺寸和实测尺寸 | 声明字段的权威性 |
| L3-06 | 漏标 | 参考目标与标注对象一一匹配后无对应 | 独立目标参考 |
| L3-07 | 虚标 | 标注对象与参考目标不匹配 | 独立目标参考 |
| L3-MIS | 覆盖不足/过度 | 对齐参考后的面积或时段覆盖比 | 参考覆盖范围 |

一个样本可以同时属于多个缺陷档；八类计数不相加。输入标注本身不是独立预测区域，不能用它证明漏标、虚标或边界正确。

## 4. 定位容差

以下是当前项目默认值，除非组委会另行下发，不称为官方容差：

| 定位类型 | 命中条件 |
| --- | --- |
| 矩形框 | IoU ≥ 0.50，或归一化中心距离 ≤ 0.05 |
| 多边形 | IoU ≥ 0.50；边界 Hausdorff 距离默认 ≤ 3 像素 |
| 时间区间 | 起止端点误差 ≤ 2 秒，且参考区间重叠率 ≥ 0.50 |
| 尺寸字段 | 最大相对尺寸误差 ≤ 0.02 |

没有独立参考时，定位状态为 `candidate`，保留预测框/时段和理由；有参考时输出 `hit`、IoU、距离、重叠率和所用容差。EPB 如果原始标签只有矩形，系统保留矩形，不把它伪装成多边形。

## 5. 污染指数与排序

对每个缺陷类别 `c`：

```text
PI_c = 100 × Σ_i [ p(i,c) ≥ threshold_c ] · p(i,c) / N
PI_total = Σ_c PI_c
```

默认八类阈值均为 `0.50`。`N` 是登记样本数，缺概率的样本仍留在分母并单列。确定性规则确认的问题在该诊断指标中使用 `p=1`，不等于模型置信度，也不等于官方召回率。污染指数越低越好，按 `PI_total` 升序排序；相同指数保留并列，目录名只用于显示顺序。

## 6. 专家异常值与融合

若运行记录保存了多个专家的原始概率，使用 `median + MAD` 审计：

```text
robust_z_i = |p_i − median(p)| / max(1, 1.4826 × MAD)
```

默认 `robust_z > 3.5` 标记为异常，记录专家名、原始值、统计量和剔除原因，再对剩余值取均值。少于 3 个专家或 MAD 为 0 时不静默剔除，保留全部有限输出并记录回退。没有原始概率时不伪造异常值处理结果。

## 7. 评分卡、程度、影响和回查

每个问题记录至少包含：样本 ID、缺陷代码、状态、概率、程度指标及单位、影响说明、文件路径、JSON Pointer 或图像区域/时间段、证据 ID、规则版本和输入哈希。样本级问题可去重计入确认技术分；类别污染指数允许重叠计入。

评分卡包含：

- 六维技术观测分、适用分母、完成比例和未决区间；
- 八类确认/候选样本数、超阈值数、概率和、污染指数贡献；
- 定位覆盖与独立参考命中指标（无参考则明确显示不可计算）；
- 主要缺陷、程度、影响和下一步；
- 可下载的 JSONL 台账、哈希清单、运行日志和版本信息。

## 8. 当前不能宣称“全部达标”的原因

系统功能已经补齐了污染指数、容差配置、独立参考门控、专家异常审计接口和前端展示；但下列条件仍依赖外部材料或指定环境：

1. 路演包没有独立八类逐样本真值，不能报告官方 Precision/Recall/F1；
2. 部分包缺字段字典、用途声明或来源材料，六维对应分数只能是未决或限定技术观测；
3. EPB 的源标签可能只有矩形，不能声称已有独立多边形标注；
4. 指定硬件的完整端到端运行收据、最终 Docker save tar 和正式视频需要在提交环境复核。

这不是把数据缺失归咎于系统，而是防止把“未提供证据”错误写成“已通过”。
