## 3. 六个 agent YAML 的关键内容

### `manifest.yaml`

- 名称：`opc-evidence-first-agent`；版本：`0.1.4`。
- 编排：`pipeline`；单进程、确定性；全局种子 `20261021`。
- 运行时：Python `>=3.10`，网络关闭，不要求加速器。
- 护栏：输入只读，写入仅允许 `OUTPUT_ROOT`，模型 token 配额为 0，审计写入 `run.log.jsonl`。
- 子代理为空；当前算术和证据生成不依赖不确定的多代理协商。

### `tools.yaml`

五个工具覆盖 C01–C12：清单、关系配对、标注字段、同源差异和文档检查。工具均登记版本、确定性、超时、重试上限和失败方式；失败默认记录并降级为可见的待判定状态，不伪装成通过或不适用。

### `skills.yaml`

领域技能覆盖图像标注、事件目录、分割和时间序列。它定义四状态判定、clean/P0 参照、图像变化后的几何对齐、类别契约、CME 时间字段、ULF 采样率/覆盖量以及“没有独立真值时不能宣称官方 P/R/F1”的边界。

### `rules.yaml`

规则重点是证据链和失败可见性：缺少语义参考时保留待判定；定位器为空时禁止输出结论；工具异常要写入日志；适用但未实现的检查必须留在完成度分母；不可复算的模型声明不能升级为确认问题；不可计算维度不能填 0 或 100。

### `memory.yaml` 与 `plugins.yaml`

记忆只服务于当前运行，输出产物是唯一可交接记录；插件默认关闭，避免运行时从外部加载未审计代码。外部 DeepSeek/Qwen 只能组织已有证据的解释，不能修改问题状态、分数、排序和证据。

## 4. `source/` 应包含的内容

交付时建议从仓库复制以下内容到 `source/`：

```text
source/
├─ src/spaceqa_agent/       # 规则引擎、审计、评分、Web、对话和复核协议
├─ tests/                   # 单元测试和协议测试
├─ scripts/                 # 复现、审计、报告导出脚本
├─ configs/                 # 外部路径模板和源码清单
├─ experiments/             # 研究协议和实验脚本
├─ docs/                    # 架构、数据约定、部署和评价规范
├─ pyproject.toml           # 包名、版本、入口和依赖声明
├─ Dockerfile
├─ docker-compose.yml
├─ README.md / README.en.md
└─ THIRD_PARTY_NOTICES.md
```

真实数据、原始标签、模型权重、预测缓存、运行目录和 API Key 不应放入 `source/`，也不应写入 Git 或客户端包。

## 5. `06_问题清单` 的报告口径

`findings.jsonl` 是机器可读明细，`findings_report.md` 是人可读汇总，两者必须使用同一冻结运行、同一 `runId`、`ruleVersion` 和 `specVersion`。路演材料中应明确：

1. 规则确认问题与模型候选分开保存；候选概率不是官方准确率。
2. 12 包共 24,782 条登记样本；报告统计了数据文件缺失、位置偏差、类别契约冲突、时间疑点、尺寸矛盾、漏标、虚标和覆盖问题。
3. `findings.jsonl` 的“记录条数”与报告中的“问题样本数”不是同一个统计单位，同一条样本可能有多个 finding，不能直接相加。
4. 路演包缺少独立八类缺陷真值时，只能给出可回查发现、污染指数、定位层级和技术展示排序，不能把结果写成官方 Precision、Recall 或 F1。
