# 交接审计：未完成事项与开发计划

更新时间：2026-11-08。本文用于交接和下一阶段分工。`已实现`只表示仓库中有代码或可复核历史产物；`已验证`还要求在冻结输入、冻结版本和指定硬件上重新运行。没有独立参考答案的结果保留为技术代理或候选，不能写成官方 Precision、Recall、F1 或关键缺陷召回率。

## 结论先行

当前可以交接的主线是：规则扫描、样本/标签配对、八类候选账本、六维状态、证据索引、评分/排序程序、浏览器工作台和离线规则运行时。以下事项仍阻止“全部交付达标”声明：

1. 路演/隐藏集没有独立的九类缺陷真值，尤其缺少实例级位置和时间端点参考，因此官方九类 P/R/F1 与关键缺陷召回尚不能计算。
2. 0.6.0 的 20GB 收据和 A100 全量前向已有记录，但指定 A10 上的完整单包 3 小时、峰值显存和资源收据尚未完成。
3. 当前代码以八类缺陷账本为主；官方材料中的“九类”需补齐一份明确的代码映射，确认孤儿标注（例如 LO-03）是否进入统一接口、统计和前端。
4. 交付包还需要从同一次冻结运行复制完整评分卡、排序、问题清单、证据、日志、PDF、Docker save tar 和视频，仓库中的源文件不能替代这些收据。

## 推荐开发顺序

1. 先冻结版本、环境、分组清单和交付目录，停止修改评分口径。
2. 补九类代码映射和独立盲评真值，优先解决孤儿标注、漏标、虚标和定位参考。
3. 在 A10 上完成单包端到端 3 小时/显存验收，同时保存完整日志。
4. 以冻结 test group 重跑 HGB7/八类头，生成每类、每包和全局指标，禁止混用历史缓存指标。
5. 再补严重程度、六维材料和最终排序，最后生成 PDF、Docker tar、证据包和演示视频。
