# 官方限制与硬件耗时

## 官方硬约束

根据比赛评分与交付要求，完整 Docker 镜像和 `docker save` 原始 tar 都不能超过 **20,000,000,000 字节**；单个数据集的完整评价不超过 **3 小时**。运行应能在无网络、单次、无状态环境中 load、run 并写出评分卡、排序、问题清单、证据索引和日志。

## 0.6.0 压缩发布实测

| 项目 | 实测 | 结论 |
| --- | ---: | --- |
| Docker 镜像 | 19,748,024,384 bytes | 低于 20 GB |
| Docker save 原始 tar | 19,748,043,776 bytes | 低于 20 GB |
| 专家数 | 21 | 全部保留 |
| 测试记录 | 18,450 | 覆盖六类、P0–P4、30 包 |
| A100 GPU1 全量真实前向 | 3,124.28 s | 约 52.1 min |
| Qwen NF4 专家 | 2,480.62 s | 约 79.4% 的全量时间 |

压缩前后总体技术代理指标完全一致：Precision 0.9515306、Recall 0.9495121、F1 0.9505203，TP=2238、FP=114、FN=119、TN=82330。逐类型 F1 为 AIA 0.8919、HMI 0.8878、CME 0.9992、EPB 1.0000、DMSP 0.8758、ULF 1.0000。

这些指标由公开 P0 对照派生并按已知位计算，是压缩前后等价性检查的技术代理，不是组委会独立九类缺陷真值，也不是路演包的官方成绩。

## 目标硬件评估

A100 40GB 的全量实测满足 3 小时要求，按实际吞吐估计最大公开包约 30 分钟量级。当前尚未在官方指定 A10 24GB 上完成正式端到端验收：Qwen NF4 在 A100 上的峰值显存约 30.8GB，直接照搬 batch 可能超出 A10 显存。建议在 A10 依次测试：

1. Qwen micro-batch 由 16 降至 4 或 8，保持确定性预处理；
2. 非 Qwen 专家按阶段加载并及时释放显存；
3. 记录单包的加载、预处理、21 专家前向、输出和审计时间；
4. 记录峰值显存、CPU/RAM、镜像大小和网络状态；
5. 用 `under_3h=true`、`under_20gb=true` 和哈希清单作为可交付验收条件。

因此目前的准确表述是：**完整压缩包和 A100 全量测试已满足限制；A10 具有较大时间余量的可能，但显存和端到端时限仍需在指定机器复测确认。**
