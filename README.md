## 从哪里开始

1. 阅读 02_部署与使用说明.md，按 image/archive.sha256 校验并加载镜像。
2. 打开 交付导航.html 查看十二目录技术分和评分卡。
3. 从 06_问题清单/findings.jsonl 的 findingId、checkId、evidenceRef，转到 07_证据索引/evidence_index.csv 和实际证据 JSON。
4. 查看 08_运行日志/交付整理/交付核查报告.md 及核查回执，了解结构核对与科学证据边界。
5. 用 sha256sum -c SHA256SUMS.txt 检查交付字节；用 python3 source/scripts/validate_delivery.py --root . 复核已有产物。该脚本只读文件，不重新评价数据或调用模型。

## 结果口径

现行排序按 100 ×（1 − 已确认可计分或待核的去重样本数 / 全部登记样本数）。共 3,658 / 24,782 个样本，含待核错误率 14.76%。待核仍标记为待核。同率并列。

12 个目录均有六维技术证据下界及待证区间，见 13_六维评分修复_20261110/六维证据覆盖复算/。六维采用证据覆盖修正。分项下界只计已证实通过，上界将仍待证的适用项纳入可能通过，确属不适用的项排除。先按检查归一，再维内合成和六维等权平均。局部检查及适用未完成项逐项列示，重合的已执行检查仅保留诊断。下界用于保守技术比较，完整科学合分待独立证据。主榜继续按确认与待核样本并集率排序。正式科学六维总分及主办方计分仍需其适用的独立依据。PPT 保留历史展示口径，现行数字以评分卡和 CSV 为准。
